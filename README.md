# ACQUIRE — ブラウザ版

ボードゲームの古典的名作「アクワイア」のブラウザ実装です。
ホテルチェーンを設立し、株を買い、合併ボーナスで資産を増やして、
ゲーム終了時に一番お金を持っていた人が勝ちます。

CPU は**ルールベース**（学習・探索木なし）。すべての選択肢を「期待ドル」に
換算して比較する評価関数で動いています。

## 遊びかた

いちばん簡単なのは、単一ファイル版をブラウザで開くだけ：

```
dist/acquire.html   ← ダブルクリックで起動（サーバー不要）
```

開発用に元のファイル構成で動かす場合：

```bash
npm run serve     # http://localhost:8080
```

`index.html` を直接 file:// で開いても動きます（ES modules を使っていないため）。

## 実装した内容

### ルール（Avalon Hill 版に準拠）

- 12×9 = 108 マスの盤面、7 つのホテルチェーン（安価 2 / 中価格 3 / 高価格 2）
- 各チェーン 25 株、初期資金 $6,000、手札 6 枚
- **設立**: 無所属タイルに隣接して置くと新チェーン設立、設立者は無料で 1 株
- **拡大**: 既存チェーンに隣接して置くとチェーンが伸び、株価が上がる
- **合併**: 大きい方が存続。同数なら置いた人が選ぶ
  - 消滅チェーンの筆頭株主に株価 ×10、第 2 位株主に ×5 のボーナス
  - 同数で並んだら分割（$100 単位で切り上げ）。株主が 1 人なら両方受け取る
  - 消滅株は「売却 / 2 株→存続 1 株に交換 / 保持」から選択
- **安全圏**: 11 マス以上のチェーンは吸収されない。安全圏同士をつなぐタイルは永久に配置不可（手番終了時に交換）
- 7 チェーンすべてが盤上にある間は設立できない（そのタイルは一時的に配置不可）
- **終了条件**: 41 マス以上のチェーンが出る、または盤上の全チェーンが安全圏。
  手番プレイヤーが宣言 → 全ボーナス支払い + 全株を時価清算

### 演出

タイルが手札から盤面へ飛ぶ、チェーン設立時のリップルとフリップ、合併時の
画面シェイクと吸収アニメーション、ボーナスの浮き上がる金額表示、株券が
飛ぶ演出、所持金のカウントアップ、終了時の紙吹雪など。
WebAudio による効果音付き（ヘッダーの ♪ でオン/オフ）。
`prefers-reduced-motion` を尊重します。

演出スピードは開始画面で「ゆっくり / ふつう / はやい」から選べます。

### 構成

| ファイル | 役割 |
| --- | --- |
| `js/rules.js` | 盤面座標・チェーン定義・株価表（変わらない事実だけ） |
| `js/engine.js` | 状態遷移とルール判定。DOM には一切触れない |
| `js/ai.js` | ルールベース CPU |
| `js/ui.js` | 描画とアニメーション再生 |
| `css/styles.css` | スタイルと `@keyframes` |
| `build.js` | 単一 HTML への結合 |

エンジンは演出キュー `state.fx` にイベントを積むだけで、UI 側がそれを
順番に再生します。この分離のおかげで、エンジンは Node 上でそのまま
高速に回せます（下記のテスト）。

## CPU の考えかた

すべての選択肢を **期待ドル** に換算して比較します。単位が揃っているので
「設立」「拡大」「合併」「捨て牌」を直接比べられます。

- **株の価値**: 株は最終清算でそのときの株価に戻る → 値上がり分が利益。
  残りタイル数からチェーンの伸びを見積もり、将来株価で評価する
- **ボーナスの重み**: 筆頭 = 株価 ×10 / 第 2 位 = ×5。つまり株価が $100 上がると
  筆頭株主の取り分は $1,000 増える。地位の改善は株数以上に効く
- **合併の評価**: 自分が取れるボーナスは満額加点、他人に渡る分は `rival` 係数で減点
- **購入**: 1 株ずつ貪欲に選ぶ。「その 1 株でボーナス地位がどう変わるか」を
  実際に株数を +1 して再計算し、差分で評価する
- **終了宣言**: 今終わったら自分が 1 位かを正確に計算し、勝っているときだけ宣言する

`rival`（相手の利益をどれだけ嫌うか）は実測でチューニングしました
（0.2 → 22.0%、0.5 → 26.4%、**0.7 → 29.1%**、1.0 → 26.0%、1.8 → 20.0%）。

性格は 4 種類（バランス / アグレッシブ / キャッシュ重視 / マージャー）。
4 人戦での勝率は 21〜33% に収まっていて、どれも実用的な強さです。

## テスト

```bash
npm test            # ルール不変条件の検証（CPU 同士で 300 ゲーム）
npm run bench       # CPU の強さ比較
npm run test:browser  # 実ブラウザ(Chromium)での操作確認
```

### `npm test` が確認していること

毎手ごとに以下をチェックします（2〜6 人戦、全フェーズ）：

- 各チェーンの株が常に 25 枚（銀行 + 全プレイヤー）
- 所持金・銀行在庫が負にならない
- 盤上 + 手札 + 山札 + 箱に戻した死にタイル = 108 枚、重複なし
- 各チェーンが 1 つの連結成分であること、1 マスのチェーンが存在しないこと
- CPU が非合法手を打たないこと（在庫超過・資金超過・4 株以上の購入・奇数枚の交換など）
- 清算後、盤上に残るチェーンの株がすべて銀行に戻ること

```
300 ゲーム / 平均 20.5 ラウンド・設立 10.7 回・合併 6.6 回
✅ すべての不変条件を満たしました
```

### CPU の強さ（席順ローテーション、400 ゲーム）

| | 勝率 | 平均資産 |
| --- | ---: | ---: |
| ルールベース CPU | 50.0% | $46,629 |
| 初期版の CPU | 2.8% | $28,480 |
| ランダム | 0.3% | $20,735 |
| ルールベース CPU | 47.0% | $47,127 |

ランダム 3 体を相手にした場合の勝率は **92.0%** です。

### `npm run test:browser`

実際に Chromium を起動して、コンソールエラーが出ないこと、CPU 同士の対戦が
自動進行すること、タイル配置と株購入の操作が通ること、1 ゲームを最後まで
完走して結果画面が出ること、モバイル幅で横スクロールが発生しないことを
確認します。スクリーンショットは `dist/shots/` に出力されます。

## アクセス解析

GitHub Pages で配信しているときだけ、Google アナリティクスを読み込みます。
[PLAYBENCH](https://shunshun0904.github.io/playbench/) と同じ測定IDで、
**どのゲームが遊ばれているか**を1つのプロパティで見るためのものです。
集めるのは読まれたページと、おおまかな地域・機器の別だけです。

読み込まない条件が3つあります。

1. `index.html` を**ファイルとして開いたとき**（`file://`）── 何も読み込みません
2. ブラウザが**追跡拒否**を出しているとき（Global Privacy Control / DNT）
3. PLAYBENCH の奥付で**「止める」**を押したとき
   ── 6サイトとも同一オリジンなので、その設定はここにも効きます

該当箇所は `index.html` の `<head>` にある `<script>` 1つだけで、
行き先は `https://www.googletagmanager.com/gtag/js` のみです。
